The ratio of the number of [[warp|warps]] resident on a [[streaming multiprocessor]] to the most it can hold. A read from GPU memory takes hundreds of cycles, and the scheduler hides this latency by switching among resident warps: while one waits for data, it issues instructions from another. The more registers each thread uses and the more [[memory hierarchy|shared memory]] each block uses, the fewer warps can be resident at once.

Note: Occupancy only needs to be high enough to hide latency; higher is not always better. Beyond that point, each thread gets fewer registers and data travels more often to and from GPU memory. High-performance [[kernel|kernels]] such as matrix multiplication often accept lower occupancy on purpose in exchange for more registers per thread, hiding latency with independent instructions within each thread.

Example: Each SM of the A100 has 65536 registers and holds at most 64 warps. If each thread uses 128 registers, a warp needs $32 \times 128 = 4096$, so at most 16 warps fit and the occupancy is 25%; with 32 registers per thread, all 64 warps fit.
