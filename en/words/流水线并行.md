A form of parallelism that divides a model by layers into stages placed on different GPUs, which process the data in turn. When a stage finishes, it passes its activations to the next; communication happens only between stages and is much smaller than in [[tensor parallelism]]. To keep later GPUs from waiting idle, a batch is split into micro-batches so that the stages work on different micro-batches at the same time.

Note: It lowers only the memory per GPU, not the latency of a single request: a token still has to pass through every stage in turn. Its strength is low communication, which suits spanning several machines or GPUs without fast interconnects; in inference, the stages stay busy by processing different requests at the same time.

Example: A 32-layer model is split across 4 GPUs, 8 layers each. With a single micro-batch per batch, only 1 GPU computes at any moment, a utilization of just 25%; with several micro-batches, all the GPUs can work at once.

Paper: [GPipe: Efficient Training of Giant Neural Networks using Pipeline Parallelism](https://arxiv.org/abs/1811.06965) (Huang et al., 2018)
