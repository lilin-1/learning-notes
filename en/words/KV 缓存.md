When a [[language model]] generates [[token|tokens]] one by one, the practice of storing the keys and values that each layer's [[self-attention]] has already computed, for reuse in later steps. Because of the [[causal mask]], the keys and values at generated positions do not change as later tokens arrive, so each step computes one query, key and value, for the new token only. The cache size is proportional to the number of layers, the sequence length and the key–value dimension.

Note: This trades memory for computation. Without the cache, generating $n$ tokens one by one computes keys and values for $1 + 2 + \dots + n \approx n^2 / 2$ positions in total; with it, only $n$. The price is a cache that grows linearly with sequence length and concurrency; with long sequences and many concurrent requests, it can take more GPU memory than the model weights themselves.

Example: To generate token $t$ without the cache, keys and values must be recomputed for $t$ positions; with it, for only $1$. Take the smallest GPT-2: 12 layers and $d = 768$, so each position has 768 numbers in its key and 768 in its value. For 1024 positions that is $2 \times 12 \times 768 \times 1024 \approx 18.87$ million numbers, about 38 MB in 16-bit floating point.
