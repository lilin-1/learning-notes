Cutting matrices into small tiles that a thread block loads jointly into [[memory hierarchy|shared memory]] and then reuses repeatedly, in order to raise the [[arithmetic intensity]]. To compute $C = AB$, $T \times T$ threads take one $T \times T$ tile of $C$. In each round, every thread moves one number of $A$ and one of $B$ from GPU memory into shared memory; once the whole tile has arrived, every thread performs $T$ multiply–adds with one row and one column from shared memory. Each number in shared memory is used by the $T$ threads of its row or column, yet read from GPU memory only once.

Note: Each round passes two barriers: one after loading, so that every number needed has arrived, and one after use, so that the next tile does not overwrite numbers someone is still reading. The tile size is a trade-off: larger tiles mean more reuse, but shared memory is limited, and oversized tiles leave fewer blocks resident and lower the [[occupancy]]. High-performance matrix multiplication tiles once more at the register level.

Example: Take $4 \times 4$ matrices with $T = 2$ and the top-left $2 \times 2$ tile of $C$. Without tiling, 4 threads each read a row of $A$ and a column of $B$ from GPU memory, $4 \times 8 = 32$ reads in all. With tiling there are two rounds, each loading one $2 \times 2$ tile of $A$ and one of $B$, $2 \times 8 = 16$ reads in all. In general, the reads fall from $2n^3$ to $2n^3 / T$.
