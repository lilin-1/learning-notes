A sequence of operations in [[CUDA]] that execute in order, such as copies and [[kernel]] launches. Operations in the same stream run one after another, and a later one never overtakes an earlier one; operations in different streams do not wait for each other and can run on the GPU at the same time. Operations placed in a stream are asynchronous with respect to the host: the call returns at once, the host can do other work, and it waits with `cudaStreamSynchronize` when it needs the result.

Note: Streams let copies overlap with computation: the data is split into chunks, and while one chunk is computed, the next is already being copied. This requires the [[host and device|host memory to be pinned]]; otherwise the copy falls back to synchronous behavior. Order between streams is expressed with events: one stream records an event and another waits for it to complete. The driver maps streams onto a number of hardware work queues, 8 by default; with more streams than queues, streams sharing a queue can be wrongly serialized.

Example: Each of 4 chunks must be copied in, computed and copied out, each step taking 1 millisecond. With a single stream this takes $4 \times 3 = 12$ milliseconds. With 4 streams, and one copy engine each for copying in and copying out, the three steps are staggered and overlap, taking about $4 + 3 - 1 = 6$ milliseconds.
