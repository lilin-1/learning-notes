The software through which the operating system and applications use a [[graphics processing unit|GPU]], in two parts, kernel mode and user mode. The kernel-mode driver runs in the operating system kernel: it initializes the GPU, allocates GPU memory, maintains the GPU's page tables and sets up, for each application, the channels through which commands are submitted. The user-mode driver is a library inside the application process that translates calls of the programming interface into commands the GPU can read.

Note: The split is for speed. Setting up channels and allocating memory go through the operating system. After that, each kernel launch or copy only requires the user-mode driver to write commands into memory mapped into the process and write once to a doorbell register, with no system call. The operating system is normally off this path and steps in only to allocate resources and to handle interrupts and errors. When several processes share a GPU, the kernel-mode driver sets the order in which their channels take turns.

Example: On Linux, the kernel-mode driver is the module `nvidia.ko`, which processes talk to through the device file `/dev/nvidia0`; the user-mode driver is `libcuda.so`. The driver version shown by `nvidia-smi` refers to this pair.
