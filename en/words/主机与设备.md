The terms a programming model uses for the CPU and the [[graphics processing unit|GPU]]: the host is the CPU with its memory, and the device is the GPU with its memory. Each has its own physical memory, and the two are connected by the PCIe bus. Data must be copied explicitly between them, moved by the GPU's copy engines through direct memory access (DMA), without occupying the CPU.

Note: PCIe has only a small fraction of the bandwidth of GPU memory, and moving data back and forth often takes longer than the computation itself, so a model's weights, once copied into GPU memory, stay there. During a copy, the host pages must not be swapped out by the operating system, so ordinary memory is first copied by the driver into a pinned (page-locked) buffer before transfer. Allocating pinned memory directly skips this step and lets copies overlap with computation.

Example: PCIe 4.0 carries 16 Gbit/s per lane with 128b/130b encoding, so 16 lanes give about $16 \times 16 \times \frac{128}{130} \div 8 \approx 31.5$ GB/s in each direction. Copying 14 GB of weights to the GPU takes about 0.44 seconds, whereas reading them once from A100 memory takes about 7 milliseconds.
