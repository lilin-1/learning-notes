Reusing the [[KV cache]] of a common prefix across requests. Because of the [[causal mask]], the key and value at a position depend only on that position and the [[token|tokens]] before it, so requests with the same prefix have exactly the same keys and values over that prefix. This part can be computed once and shared, which saves the repeated [[prefill and decode|prefill]]. Shared system prompts, multi-turn conversations and few-shot examples all qualify.

Note: A hit requires the tokens to match one by one, so content shared by requests belongs at the very start of the prompt, followed by the parts that differ. A difference of even a single token in the prefix makes all the cache after it unusable. Prefix caching changes no output and only saves computation; the price is that cache blocks are kept longer, occupying memory that could otherwise go to new requests.

Example: 100 requests share a 2000-token system prompt, and each adds 100 tokens of its own. Without reuse, $100 \times 2100 = 210{,}000$ tokens must be prefilled; with reuse, only $2000 + 100 \times 100 = 12{,}000$.
