The configuration data written into an [[FPGA]]. It specifies, bit by bit, the truth table of every lookup table, the state of every wiring switch, and the operating modes of the multiply–add units and memory blocks along with the initial contents of the memories. It is generated from a design written in a hardware description language such as Verilog, or through high-level synthesis, by synthesis, placement and routing. Mainstream FPGAs lose their configuration when powered off and reload it from flash memory or from the host at every power-up.

Note: A bitstream determines the circuit itself, not a program that runs on the circuit. Loaded with one bitstream, a chip is an inference engine for some model; loaded with another, it becomes a network card, a video encoder or even a processor. Partial reconfiguration further allows one region of the chip to be rewritten while the rest keeps running. The price is that generating a bitstream often takes hours, and changing a single detail of the design means generating it again.

Example: A 2-input lookup table stores 4 bits, corresponding to the inputs 00, 01, 10 and 11 in turn. Storing 0001 makes it an AND gate, 0110 an XOR gate and 0111 an OR gate. A 6-input lookup table stores 64 bits and can implement $2^{64}$ different functions.
