# How can a kernel be made to run faster?

First use [[arithmetic intensity]] to decide what limits it. A memory-bound [[kernel]] must move less data: [[memory coalescing]] makes every transfer count, [[kernel fusion]] eliminates round trips of intermediate results, and [[tiling]] lets data that has been read be used many times. A compute-bound kernel must use the right arithmetic units: matrix multiplications belong on [[Tensor Core|Tensor Cores]].

Next, keep the hardware busy. The [[occupancy]] must be high enough to hide memory latency, and the number of thread blocks should far exceed the number of [[streaming multiprocessor|streaming multiprocessors]], to avoid the tail effect. When many very short kernels run back to back, launch overhead itself becomes the bottleneck, and a [[CUDA graph]] can remove it.

These arrangements are tedious to write. [[Triton]] lets a program describe only which block of data each thread block processes, leaving the details within the block to the compiler.
