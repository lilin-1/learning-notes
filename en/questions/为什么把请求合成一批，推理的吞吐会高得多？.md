# Why does batching requests raise inference throughput so much?

Because [[prefill and decode|decoding]] is limited by memory bandwidth: every step reads all the weights from GPU memory once, and that one read is shared by every sequence in the batch. The larger the batch, the less reading each output [[token]] bears and the higher the [[arithmetic intensity]], until compute or the capacity of the [[KV cache]] becomes the new bottleneck.

Keeping batches both large and full takes two more things. [[PagedAttention]] allocates the cache on demand, so the same memory holds more concurrent sequences; [[continuous batching]] lets finished sequences give up their places at once, so the batch stays full. [[prefix caching|Prefix caching]] also saves the repeated prefill of shared prefixes. [[vLLM]] is an inference engine that brings all of these together.

Example: A 7-billion-parameter model on a GPU with 2 TB/s of bandwidth generates at most about 143 tokens per second for a single sequence. With a batch of 64 and negligible cache reads, one read serves 64 sequences, and the throughput limit is about 9100 tokens per second.
