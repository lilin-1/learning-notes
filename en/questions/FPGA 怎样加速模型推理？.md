# How do FPGAs accelerate model inference?

By tailoring a circuit to the model instead of executing instructions. A [[graphics processing unit|GPU]] runs programs on one fixed set of arithmetic units, so every model is first turned into a sequence of [[kernel|kernels]]. An [[FPGA]] instead loads a [[bitstream]] that lays out the model itself as a circuit: each operator gets its own block of logic, and data flows from one block straight into the next. This organization is called a [[dataflow architecture]]: there is no overhead for fetching instructions or launching kernels, and intermediate results stay on the chip, in effect [[kernel fusion|fusing]] the whole model into one kernel.

Matrix multiplication is often built as a [[systolic array]], in which each number read travels along the array and is reused by many multiply–add units, giving high [[arithmetic intensity]] without large caches. Bit widths can also be chosen freely: [[quantization|quantized]] to 4 bits or fewer, a multiplier needs very little logic, so the same area holds more multipliers and the same bandwidth reads more weights.

These advantages are clearest in small-batch, low-latency settings. At batch size 1, [[prefill and decode|decoding]] is bandwidth-bound and most of a GPU's compute sits idle, whereas an FPGA's circuit can be designed around the pace of a single request, with stable latency and lower power. Its limits are peak compute and bandwidth below those of GPUs of the same generation, and far slower development and compilation. So large-model inference still runs mainly on GPUs, and FPGAs serve mostly where latency is critical, power is constrained or the model is fixed.
