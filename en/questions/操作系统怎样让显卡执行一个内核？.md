# How does the operating system get a GPU to run a kernel?

For the most part the operating system is not involved; it appears only at the start. The kernel-mode part of the [[GPU driver]] initializes the GPU, allocates memory, sets up channels for the process, and maps each channel's control area and the doorbell register into the process's address space. From then on, work is submitted entirely in user mode.

When a program calls the launch interface, the user-mode driver first writes the kernel's arguments and a launch descriptor into GPU memory. It then appends a launch command to the [[command buffer]], advances the tail pointer and writes the doorbell once. The GPU's front end fetches the command and reads the launch descriptor: the dimensions of the grid and of each [[thread block]], the shared memory per block, the registers per thread, and the address of the [[kernel]] code.

A distribution unit then sends the thread blocks one by one to [[streaming multiprocessor|streaming multiprocessors]] with spare resources. Each block is split into [[warp|warps]], whose instructions the schedulers of the partitions issue in turn; when a block finishes, the resources it frees go straight to the next block. After the launch command, the driver adds a command that writes a semaphore; the GPU executes it once all the blocks have finished, which tells the driver the kernel is done.

Example: Launching a kernel of 4096 thread blocks with 256 threads each takes the CPU a single launch command. If each A100 SM holds 8 blocks at once, the 108 SMs take 864 blocks in the first round, and the rest follow as earlier blocks finish.
