# Where does the memory go when training a large model?

To four places: parameters, gradients, optimizer state and [[activation|activations]]. With [[mixed-precision training]] and [[Adam]], the first three take 16 bytes per parameter: 2 bytes each for the 16-bit parameter and gradient, and 12 bytes for the 32-bit master weight and the two moments. Activations grow with the batch size and the sequence length, and for long sequences they are often the largest item.

Each way of saving memory targets one item. [[ZeRO]] shards parameters, gradients and optimizer state across the GPUs of [[data parallelism]]. [[activation recomputation|Activation recomputation]] stores only checkpoints, trading an extra forward pass for activation memory; [[gradient accumulation]] splits a large batch into small ones, so memory need hold the activations of only one. [[tensor parallelism|Tensor parallelism]] and [[pipeline parallelism]] cut the model itself apart.

Example: For a 7-billion-parameter model, the first three items take $16 \times 7 = 112$ GB, already more than an 80 GB GPU; for inference, the 16-bit weights need only 14 GB. Of the 98 GB that training needs beyond inference, the optimizer state takes 84 GB.
