# How is an encoder–decoder model trained, and how does it translate?

In training it sees the whole translation at once; in translation it can only generate token by token. Both use the same network.

Training uses sentence pairs. The [[encoder]] reads the whole source sentence, its [[self-attention]] carries no mask, and every [[token]] sees the full sentence. The [[decoder]]'s input is the translation shifted right by one, which is [[teacher forcing]]: the context at every position is the true translation, the [[causal mask]] ensures that each position looks only backward, and [[cross-attention]] reads the encoder's output. Each position predicts the next token, the [[cross-entropy]] with the true token is computed, and gradients flow all the way back into the encoder, so the two are trained together.

In translation, the encoder computes the source sentence once, and the keys and values used by cross-attention are also computed once. The decoder starts from a start token; each step gives a distribution over the next token, one is chosen and appended, and the next step follows, with the keys and values of earlier steps kept in the [[KV cache]]. Tokens are usually chosen by [[beam search]], stopping at an end token or at a length limit. In training the context is the true translation, but in translation it is the model's own output; this mismatch is called [[exposure bias]].

Example: The original [[Transformer]] was trained on about 4.5 million sentence pairs of the WMT 2014 English–German data. In translation it used a beam width of 4 and a length penalty $\alpha = 0.6$, with output at most 50 tokens longer than the input.
